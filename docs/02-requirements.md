# 第 2 章 生产级要求（七大项）

> [← 返回教程目录](../README.md#教程目录生产级-iot-开发教程)

## 2.1 可靠性（Reliability）

| 要求 | 本仓库已有 | 生产补强 |
|---|---|---|
| 消息不丢 | QoS 1 + clean:false 会话保持 | broker 集群 + 消息持久化 + 双活 |
| 断网不丢 | 网关 SQLite 缓存补报 | 缓存容量上限 + 补报限速（防风暴） |
| 重复无害 | 幂等去重 | 唯一键（设备+序号）+ 存储层去重 |
| 服务重启恢复 | sink 的 pending 表 | 平台无状态化 + 消息积压水位监控 |
| 乱序兜底 | 时间戳入库 | 以设备时间+序列号排序，容忍乱序 |

## 2.2 高可用（Availability）

- **Broker 集群**：EMQX 多节点（Raft 元数据 + 分布式消息），单点故障设备无感
- **网关冗余**：重要产线双网关（主备），心跳切换
- **存储多副本**：TDengine 副本数 ≥ 2，故障自动切换
- **平台无状态**：subscriber 类消费者多实例 + 负载均衡，单实例挂掉其他接管

## 2.3 安全性（Security）

- **传输加密**：MQTT over TLS（8883 端口），禁明文
- **设备认证**：X.509 证书（一机一证）或 Token + 设备密钥；禁用匿名
- **最小权限**：每台设备只能发布/订阅自己的主题（EMQX ACL 控制）
- **数据防伪**：设备上报带签名/HMAC，防中间人篡改
- **平台安全**：REST API 加 HTTPS + 认证 + 审计日志（TDengine 自带 audit）
- **密钥管理**：密码/证书不落代码，用环境变量/密钥服务（Vault）

## 2.4 可观测性（Observability）

| 维度 | 生产要求 | 对应做法 |
|---|---|---|
| 日志 | 集中收集（ELK/Loki） | 网关/平台打结构化日志（JSON），带 traceId |
| 指标 | Prometheus + Grafana | 上报率、积压数、连接数、延迟、CPU/内存 |
| 告警 | 阈值 + 通知（钉钉/邮件） | 上报中断 >N 分钟、积压 >N 条、网关离线 |
| 链路追踪 | 可选（大规模才需要） | MQTT 消息带 messageId 贯穿全链路 |

## 2.5 性能（Performance）

- **写入优化**：时序库批量写入（一次 INSERT 多行），本仓库 sink 可改为攒批 5s/1000 条提交
- **压缩**：TDengine 默认 ZSTD 压缩，注意建库参数（实际测试：10 倍+ 压缩率）
- **降采样**：原始 1s 数据 → 1min/1h 聚合表（TDengine 连续查询/流计算），历史查询走聚合表
- **连接管理**：设备侧心跳间隔 ≥ 30s；broker 连接数上限与内存规划（EMQX 单节点 ~百万连接需 8G+）
- **协议开销**：报文精简（MQTT 主题短、payload 用紧凑 JSON/二进制）

## 2.6 运维（Operations）

- **部署**：Docker Compose（开发）→ Kubernetes（生产）
- **OTA 升级**：网关固件远程升级，失败回滚（A/B 分区）
- **远程配置**：网关配置云端下发（MQTT 指令通道，已具备雏形）
- **看门狗**：硬件看门狗 + 进程守护（systemd/PM2），异常自动重启
- **备份**：时序库定期备份 + 恢复演练；配置版本化管理

## 2.7 数据治理（Data Governance）

- **保留策略**：原始数据 TTL（如 30 天），聚合数据长期保留
- **数据分层**：热数据（时序库）、温数据（时序库聚合）、冷数据（对象存储归档）
- **数据质量**：设备状态标记（在线/离线/数据可疑），异常值标记不删除
- **合规**：日志留存、数据脱敏（涉及个人信息场景）
